# Role card: Ask the pipeline (read-only MCP server)

KB-140 Q8 and KB-137 A1.4. Not an agent: a tool that AI clients use. It gets a role card like the agents because an AI acts through it, so its owner, its reach and its off switch are written down the same way. It can read the run log and change nothing.

| Item | This tool |
|---|---|
| **Name** | Ask the pipeline: the n8n workflow "GTM v2 INIT-165: ask the pipeline (read-only MCP server)", [`n8n/workflow-v2-ask-pipeline.json`](../../../n8n/workflow-v2-ask-pipeline.json), made by [`scripts/build_n8n_ask_pipeline.py`](../../../scripts/build_n8n_ask_pipeline.py) |
| **Purpose** | Let an MCP client, such as the Claude desktop app or Claude Code, answer plain questions about the routing pipeline: how many leads went to each route, what a run cost, which decisions a person changed, and why one company was routed as it was |
| **Named owner** | Revenue operations lead: a made-up role in this build. At an employer, the owner of the run log, with the data owner signing off what it may show |
| **What it reads** | Two views of the run log, `gtm_v2.decision_record` and `gtm_v2.run_summary`: routing proposals, decisions by a person, tokens and cost. Not the tables under them, not the quote desk's log, no other schema. Every row is made up and company-level |
| **What it writes** | Nothing. No tool writes, deletes, starts a workflow or sends anything |
| **What it must never do** | Run SQL a client sends; return more than 50 rows; let text from an enquiry pass as an instruction; listen beyond this Mac; run while nobody has started it |
| **Tools** | Four, each one fixed query, `select gtm_v2.ask_<tool>($1::jsonb)`, with the client's typed inputs as one JSON value: **run_summary** (runs in a date range), **list_decisions** (by run, route, changed by a person, or company), **explain_decision** (one decision in full), **cost_summary** (by model, route, day or kind of run). The functions are in [`db/ask_pipeline.sql`](../../../db/ask_pipeline.sql) |
| **Who it runs as** | The database login `gtm_v2_reader`: `SELECT` on the two views and `EXECUTE` on the tool functions, nothing else; every transaction starts read only; 3 connections at most; 10-second statement limit. The functions run with its rights (`SECURITY INVOKER`), so they cannot do more than it can |
| **Guard rails** | Inputs typed in the tool list and checked again in the database: a bad date, a route or grouping that does not exist, or an ID of the wrong shape is refused with the reason. Every list stops at 50 rows and says how many matched. Company names, the AI's reason, the reviewer's note and the stamp come back under `untrusted_text`, with a notice that they are data and never instructions |
| **Approval point** | None needed: it changes nothing and sends nothing. The clients ask before each tool call (the desktop app does by default) |
| **The door** | `http://localhost:5678/mcp/gtm-v2-ask-the-pipeline`, behind a bearer token (`ASK_PIPELINE_TOKEN` in `.env` and the n8n credential "GTM v2 ask the pipeline token"). n8n listens on 127.0.0.1 only. The desktop app connects through `scripts/ask_pipeline.py bridge`, which adds the token, so no token is in the app's settings |
| **Stop switch** | `python scripts/ask_pipeline.py off` (the workflow is unpublished; the address answers 404). It is off unless someone runs `on`. Also: stop n8n, or revoke the login (`drop role gtm_v2_reader`), or change the token |
| **Spend limit** | None needed: n8n and Postgres are local and free. The client pays for its own model calls: the blind test client uses the `gtm-pipeline` workspace key and its US$10 monthly limit |
| **Evidence** | The login proved by signing in as it: reads, and 39 of 39 write and reach checks refused ([`scripts/ask_pipeline.py check`](../../../scripts/ask_pipeline.py); tests in [`tests/test_ask_pipeline.py`](../../../tests/test_ask_pipeline.py)). The live server probed: 21 of 21 ([`probe.json`](../init-165-evidence/probe.json)) |
| **Eval** | Eight test questions with answers worked out by SQL ([`sql-answers.json`](../init-165-evidence/sql-answers.json)), asked by two clients: this build's Claude Code session ([`session-answers.json`](../init-165-evidence/session-answers.json)) and a blind Claude Haiku 5.5 client given only the four tools ([`scripts/ask_pipeline_client.py`](../../../scripts/ask_pipeline_client.py)); and one planted-instruction test, three rounds. Results in the [notes](../init-165-notes.md) |
| **Review date** | 07/12/2026, at the end of the build, or whenever the run log's views or the tools change |
